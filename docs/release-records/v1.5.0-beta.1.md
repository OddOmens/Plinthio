## What went in

Sharper artwork for video titles with no TMDB match, which fall back to a frame of the video:

- Frame covers 600 px → 1280 px; episode/title stills 480 px → 1280 px (never enlarged past the source video; JPEG quality raised).
- Stills are cached under a new file name (`…-w1280.jpg`), so old 480 px ones are simply never read again.
- The scanner finds frame covers that are exactly 600 px wide (the old size) and redoes them on the next scan, including when a TMDB key is set but the title still has no match. New frames are never exactly 600 px, so each one is redone once.
- `/api/media/cover/<id>?w=1280` is now allowed (widths: 180, 360, 720, 1280); the list lives in `THUMB_WIDTHS` and every cache-invalidation loop uses it. The pause screen asked for 780, which silently became 360, and now asks for 1280.

## Decisions

- **Server only.** The native apps live elsewhere; they should request `?w=1280` (or `raw=true`) for large cards and `/api/media/still/<id>` for stills.
- **Pre-release, minor line (1.5.0-beta.1)** since it adds an API width and reprocesses artwork; nothing users must do.

## Manual steps / follow-ups

- Re-scan each library after upgrading to refresh old frames (video grabs run through ffmpeg, so expect it to take a while on big libraries).
- Test from the Mac app on a title with no TMDB match, on a large card.
