## Why one release

The work was planned as 1.3.0 (offload, Lists, Tailscale) and 1.4.0 (two-factor, away from
home, public add-ons). Neither had shipped when both were ready, so they go out together as
the next version, 1.3.0: one upgrade for people, one changelog section, no half-state where
the Tailscale add-on exists but can't be combined with the public one.

## Decisions

- **Home-only by default for new servers; upgrades stay open.** A server set up before 1.3.0
  was reachable from outside, so it keeps that (no stored `remote_access` = on). The setup
  wizard always writes the setting. Admin → Network closes it.
- **Where a request comes from** is decided by its address (home / Tailscale / outside) with
  `TRUST_PROXY=loopback` set by the add-ons, so only a proxy in Plinthio's own network is
  believed. Funnel requests also carry `Tailscale-Funnel-Request`, which always counts as
  outside. Checked in Tailscale's source: Funnel forwards the visitor's real address.
- **A home-only server refuses outside sign-ins before checking the password**, so the
  internet can't guess passwords at all. First-run setup is home-only.
- **Two-factor is optional**, per person; admins may require it away from home, never at home.
  TOTP is implemented on `node:crypto` against the RFC 6238 test vectors; secrets are sealed
  with a key derived from `jwt.secret` (changing it means setting two-factor up again).
- **Only failed sign-ins count toward the rate limit**, so a two-factor sign-in (two requests)
  and a household behind one address don't lock themselves out.
- **Tailscale and Caddy join Plinthio's network** (`network_mode: service:plinthio`) so the
  add-ons combine and Plinthio keeps its ports.
- **Funnel is opt-in** (`TS_FUNNEL=true`); Tailscale limits its bandwidth, so the docs steer
  full-speed video to a web address of your own.
- **The Tailscale guide never handles keys:** it writes `.env` lines with a placeholder.
- **Gemini's personalization:** kept as written. Onboarding follows the roles: an admin's
  accent choice sets the server default for everyone (as the setup wizard does), while an
  editor's or viewer's is personal and only offered when the admin allows it. Locked
  settings say "Set by your admin" rather than showing in red.

## Verification

- Backend: 204 tests, including `access-and-2fa.test.js` (every rule over HTTP with addresses
  from home, Tailscale and the internet), TOTP and address unit tests, offload and
  personalization tests.
- Browser (Playwright, phone-sized): 9 tests, including the setup wizard with the Tailscale
  and Funnel guide, Admin → Network, a viewer's onboarding accent staying personal, and the
  full two-factor journey.
- Docker: base + Tailscale + public add-ons together on a scratch stack; forged addresses
  through Caddy and directly were both ignored; serve config valid with Funnel on and off.
- Test server (8089): upgraded an existing database cleanly.
- **Not tested for real:** a Tailscale sign-in and a live Funnel link, and a real domain with
  Let's Encrypt. These need accounts; the docs and Admin → Network's checks cover them.
