## Decisions

- **A minor, not a major.** A server that only pulls the new image keeps working unchanged:
  the old add-on layout (shared network, `TRUST_PROXY=loopback`) is still accepted. The three
  "may need action" items in the changelog apply to people who take the new add-on files, run
  their own reverse proxy without `TRUST_PROXY`, or keep symlinks that lead out of a library.
- **Symlinks out of a library are refused by default**, with `SYMLINK_ALLOWED_ROOTS` as the
  opt-in. The strict default is the safe one for servers we can't see.
- **CORS is off unless `CORS_ORIGIN` is set** (this reverses the 1.9.0 decision). Video streams
  keep an open read-only CORS answer so a cast receiver can fetch them.
- **The server key (`jwt.secret`) is left out of backup copies** unless turned on. An older
  copy at the destination is reported, never deleted.
- **`/api/health` still returns the version** without a sign-in: the web app's problem report
  and the TV app read it there.
- **Add-on network `10.213.47.0/29`.** The first choice (`172.31.250.0/29`) clashed with an
  existing Docker network on the first machine it was tried on, because Docker assigns from
  172.17–172.31 by itself.
- **Provenance `mode=min`**, so build arguments aren't written into the public record.

## Client impact

- `POST /api/keys` needs `password`; `POST /api/auth/2fa/setup` needs `password`.
- `PATCH /api/users/password` is session-only, takes optional `revokeApiKeys`, and answers a
  wrong current password with P107.
- `POST /api/auth/sign-out-everywhere` is session-only and deletes the account's API keys.
- Media tokens are accepted for GET/HEAD only (plus the player's stop beacon).
- New session tokens carry `typ: session`; older ones stay valid.
- Away from home with "require two-factor" on, an account without two-factor gets P112 on
  every request, not only at sign-in.
- New optional settings: `REMUX_LIMIT`, `HLS_CACHE_MAX_GB`, `SYMLINK_ALLOWED_ROOTS`,
  `PLINTHIO_7Z_BIN`, `PLINTHIO_PROXY_*`.
