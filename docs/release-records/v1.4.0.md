## Decisions

- **Minor version (1.4.0).** New features throughout, nothing users have to do when upgrading.
- **Data changes are additive.** A new `highlights` table, and new keys in each person's
  preferences (`ebookReader`, `mangaReader`). Rolling back to 1.3.1 works: the table and keys
  are ignored, so highlights and the new reader settings just aren't shown until 1.4.0 is back.
- **Backups default on.** Any server where scheduled backups were never set now backs up daily
  and keeps 7. A server where an admin turned them off keeps them off.
- **Old Admin and Settings links still work.** `?tab=settings` opens Appearance, `?tab=stats`
  opens Overview, `?tab=account` opens Security, `?tab=apikeys` opens Apps & API keys, and so on.
  Docs, error-code fixes and in-app text name the new sections; `docs/error-codes.md` was
  regenerated from `backend/src/errors.js`.

## Manual steps

1. Merge the release PR: `gh pr merge 36 --squash --admin --delete-branch`.
2. `git checkout main && git pull && git tag v1.4.0 && git push origin v1.4.0`.
3. Watch the Release workflow (about 15 minutes).
4. Redeploy 8088 from the tag (a database snapshot was also taken by hand just before, at
   `plinthio-backup-2026-10-02T01-17-59-730Z.sqlite`).
5. On 8088: Admin → Backups → *Also copy backups to* `/media/Backups/Plinthio`, Test, Save,
   and check it says "Copied to…". Then decide whether to keep or remove the host cron copy
   (`~/scripts/plinthio_backup_copy.sh`).
